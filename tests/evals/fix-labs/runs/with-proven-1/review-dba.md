## Database Review: LabResults (EF Core 10 + Npgsql)

### Critical
1. **Audit stamping (pooled context with a scoped interceptor)** `Program.cs:13-17`, `Infrastructure/AuditInterceptor.cs:8`, `Infrastructure/CurrentUser.cs:8-10`. `AddDbContextPool` builds its options once. At that moment it gets the scoped `AuditInterceptor` from the root provider, and with it a `CurrentUser` whose `Id` is fixed when it is created.
   - `IHttpContextAccessor` is per async flow, so the first request that builds the pool decides the `sub`. That is either the first clinician or `"system"`.
   - From then on every saved row gets that value in `RecordedBy`.
   - **Impact:** the audit trail on patient results is wrong, with no error. The hidden tests check `recordedBy == sub`.
   - **Fix** (`efcore-patterns` §1 and §4):
     - Make the interceptor stateless and register it as a singleton, or `new` it in the options.
     - Read the user from the context being saved: add a `CallerId` property on `LabDbContext`.
     - Register `AddPooledDbContextFactory<LabDbContext>`, plus a scoped `LabDbContext` that rents from the pool and sets `db.CallerId` from `CurrentUser` on every rental.
     - Read `CurrentUser.Id` when it is used, not in the constructor.

### Warnings
2. **Paging loses rows** `Api/ResultEndpoints.cs:55-59`. The order and the cursor use `ReceivedAt` only, and rows can share that value. A cursor of "older than the last row" skips the rest of that row's ties.
   - This happens with a fixed or fake `TimeProvider`, or with inserts in the same microsecond.
   - **Fix** (`efcore-patterns` §9):
     - Order by `ReceivedAt DESC, Id DESC`.
     - Put both in an opaque `next` cursor, e.g. `"{receivedAt:O}_{id}"` or base64.
     - Filter with `r.ReceivedAt < c || (r.ReceivedAt == c && r.Id < id)`.
     - Replace the index at `LabDbContext.cs:20` with `HasIndex(r => new { r.ReceivedAt, r.Id })`.
3. **The cursor can cause a 500** `ResultEndpoints.cs:54`.
   - A malformed `before` throws `FormatException`.
   - A valid cursor with a non-zero offset (`…+03:00`) is refused by Npgsql for `timestamptz` (`postgresql-patterns` §2).
   - **Fix:** use `TryParse` and return a 400. Use `DateTimeStyles.AdjustToUniversal` or `.ToUniversalTime()`.
4. **Unbounded column** `LabDbContext.cs:12-21`. `Notes` has no `HasMaxLength`, so it becomes `text`. That breaks the house rule (`rules/efcore-rules.md`, `postgresql-patterns` §1).
   - **Fix:** `e.Property(r => r.Notes).HasMaxLength(1000)`, or a size agreed with the clinicians.
   - Also check its length in `ResultEndpoints.cs:33`. Otherwise PostgreSQL raises `22001` and the client gets a 500.
5. **Numeric overflow causes a 500** `LabDbContext.cs:17` with `ResultEndpoints.cs:33`. `numeric(10,3)` holds at most 9,999,999.999, and nothing checks `Value`, so a larger value raises `22003`. **Fix:** check the range in the request validation.
6. **Key shape** `LabDbContext.cs:12`. Npgsql's default makes the key `GENERATED BY DEFAULT AS IDENTITY`. The house rule is `UseIdentityAlwaysColumn()` (`postgresql-patterns` §1).
7. **Connection pool sizing** `appsettings.json:3`.
   - The connection string sets no `Maximum Pool Size`, `Timeout` or `Command Timeout`. Npgsql's default of 100 per pod, times the number of pods, exceeds PostgreSQL's default `max_connections` of 100.
   - **Fix:** set e.g. `Maximum Pool Size=20;Timeout=15;Command Timeout=30` and agree the numbers with the DBA (`postgresql-patterns` §3). The password must come from a secret store, not this file.
8. **Created response differs from the stored value** `ResultEndpoints.cs:44`. The response echoes `ReceivedAt` at 100 ns precision, but `timestamptz` keeps microseconds. A client that uses this value as a cursor or compares it with `GET` sees a different instant.
   - **Fix:** truncate to microseconds before saving.

### Scan rows
- **Row 2 (`Program.cs:9`, scope validation): confirmed, and it hides finding 1** (`dotnet-core`).
  - In Development, `ValidateScopes` would throw when the pool resolves the scoped `AuditInterceptor` from the root provider.
  - Production skips that check, so the bug goes live.
  - Turn validation on only together with the fix for finding 1. Turning it on alone makes the service fail at the first request that needs the context.
- **Row 1 (`Program.cs:32`, `RoleClaimType = "realm_access.roles"`): confirmed, but it is outside my area.**
  - JwtBearer doesn't flatten Keycloak's nested `realm_access` JSON, so `RequireRole("clinician")` never matches and every clinician gets a 403.
  - Map the roles out with a claims transformation or `OnTokenValidated`. The auth reviewer should own this; I didn't load `auth-patterns`.

### Index Recommendations
- `CREATE INDEX CONCURRENTLY ix_lab_results_received_at_id ON lab_results (received_at, id);` serves the cursor at `ResultEndpoints.cs:55-58`. A btree scans backwards for `DESC`. It replaces the index on `ReceivedAt` alone.
- `IX_PatientId` (`LabDbContext.cs:21`) has no query that uses it today. Keep it only if a per-patient read is coming; otherwise it only costs writes.

### Migration Safety
- The repo has no migrations. The hidden tests create the schema from the model, and nothing calls `Migrate()`, which is good.
- For production, generate an up/down script pair. The index change in this report goes in its own script using `IsCreatedConcurrently()`, without `--idempotent`, starting with `SET lock_timeout`.
- If a table already exists, changing `notes` from `text` to `varchar(n)` rewrites and locks it. Check for oversized rows first.

### Outside my area, for other reviewers
- `NotificationQueue.cs:30` catches only `HttpRequestException`. A timeout (`TaskCanceledException`) ends the worker, and by default that stops the host.
- The queue lives in memory, so SMS messages are lost on restart; an outbox would keep them.
- `ResultEndpoints.cs:43`: when the bounded channel is full, `POST /results` blocks.
- `GET /results` returns every patient's results to any clinician. Decide whether that is intended.
