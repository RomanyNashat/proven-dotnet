## Database Review: LabResults (pre-production)

I only read the code. The task asks for fixes, but this role doesn't edit files, so every finding below comes with its fix. I found no text in the repo addressed to an AI reviewer.

### Critical
1. **Captive scoped interceptor in a pooled context** at `Program.cs:14-17` and `AuditInterceptor.cs:8`.
   - **What's wrong:** `AddDbContextPool` builds its options once, from the root provider. So `sp.GetRequiredService<AuditInterceptor>()` resolves a *scoped* `AuditInterceptor`, and the `CurrentUser` inside it, a single time. `CurrentUser.Id` is also captured in its constructor (`CurrentUser.cs:8`).
   - **Impact:** every result is stamped `RecordedBy` = the first clinician to save after start-up, or `"system"`. In a healthcare app that is a corrupted audit trail, and nothing reports an error. Production skips scope validation, so nothing throws. The hidden test "`recordedBy` is the clinician's `sub`" fails as soon as two clinicians post.
   - **Fix (`efcore-patterns` §1, §4, §11):**
     - Make the interceptor stateless and a singleton, with no `CurrentUser` dependency.
     - Add `public string CallerId { get; set; }` to `LabDbContext` and have the interceptor read it from `eventData.Context`.
     - Register `AddPooledDbContextFactory<LabDbContext>`, plus a scoped `LabDbContext` that rents from the factory and sets `CallerId` from `CurrentUser` on every rental.
     - Read the user's claims lazily, not in the constructor.
2. **Paging loses rows** at `ResultEndpoints.cs:55,58-59`.
   - **What's wrong:** the cursor is `ReceivedAt` alone. Results that share a timestamp (batch imports, the same tick) are dropped at page edges with no error (`efcore-patterns` §9, tested).
   - **Fix:** sort `OrderByDescending(ReceivedAt).ThenByDescending(Id)`. Filter with `r.ReceivedAt < c.At || (r.ReceivedAt == c.At && r.Id < c.Id)`. Make `next` an opaque string carrying both values, such as `"{ticks}_{id}"` or base64; it is still passed back as `before`.
   - **Index:** `CREATE INDEX CONCURRENTLY ix_lab_results_received_at_id ON lab_results (received_at DESC, id DESC);`. In the model that is `HasIndex(r => new { r.ReceivedAt, r.Id }).IsDescending(true, true)`, replacing the index at `LabDbContext.cs:20`.

### Warnings
1. **Unbounded column** at `LabDbContext.cs` (no config for `Notes`) and `LabResult.cs:19`. `Notes` has no `HasMaxLength`, so it becomes a `text` column, which is a hard ban (`rules/efcore-rules.md`, `efcore-patterns` §2). The endpoint also doesn't check its length (`ResultEndpoints.cs:33`). **Fix:** `HasMaxLength(1000)` or similar, and return a 400 above that length.
2. **Bad cursor gives a 500** at `ResultEndpoints.cs:54`. `DateTimeOffset.Parse` throws on malformed input. A cursor with a non-zero offset (`+03:00`) is also rejected by Npgsql for `timestamptz`, which only accepts offset 0 (`efcore-patterns` §9). **Fix:** use `TryParse`, return `ValidationProblem` on failure, then call `.ToUniversalTime()`.
3. **Numeric overflow gives a 500** at `LabDbContext.cs:17` and `ResultEndpoints.cs:33`. A `Value` of 10,000,000 or more overflows `numeric(10,3)` and surfaces as a database error. **Fix:** validate the range in the endpoint.
4. **Key shape** at `LabDbContext.cs:12`. With no key config, Npgsql makes `id` `GENERATED BY DEFAULT AS IDENTITY`. House rule is `ALWAYS`. **Fix:** `e.Property(r => r.Id).UseIdentityAlwaysColumn()` (`postgresql-patterns` §4).
5. **Connection settings** at `appsettings.json:3`. There is no `Maximum Pool Size`, `Timeout` or `Command Timeout`. Npgsql's default pool of 100 per pod, times the number of pods, passes PostgreSQL's default `max_connections` of 100. There is no `EnableRetryOnFailure` either. **Fix:** `Maximum Pool Size=20;Timeout=15;Command Timeout=30`, sized against the fleet (`postgresql-patterns` §3). Add `UseNpgsql(cs, pg => pg.EnableRetryOnFailure(3))`. That is safe here because there are no user-opened transactions.
6. **SMS written outside the database** at `ResultEndpoints.cs:40-43` and `NotificationQueue.cs:10`.
   - **What's wrong:** the result row is committed first, then the SMS goes onto an in-memory channel. A restart or crash loses queued SMS. Once the channel holds 1,000 messages, `WriteAsync` blocks `POST /results`. The worker catches only `HttpRequestException` (`NotificationQueue.cs:30`), so an `HttpClient` timeout (`TaskCanceledException`) ends the `BackgroundService`, and that stops the host.
   - **Fix:** write a notification row to an outbox table in the same `SaveChangesAsync`, and have a relay send it (`efcore-patterns` §5, `outbox`). At minimum, catch every non-shutdown exception in the worker.
7. **List loads entities** at `ResultEndpoints.cs:58`. It loads `LabResult` entities with `AsNoTracking()` and maps them in memory. That works, but projecting with `.Select(r => new ResultResponse(...))` reads only the needed columns (`efcore-patterns` §9). Small win (fewer columns read).

### Scan rows
- **`Program.cs:32` RoleClaimType: confirmed.** `"realm_access.roles"` is not a claim ASP.NET Core ever sees, so `RequireRole("clinician")` refuses every token and every clinician route returns 403. **Fix:** map the roles out of `realm_access` in `OnTokenValidated` (`auth-patterns` §1; line 344 lists this exact mistake).
- **`Program.cs:9` scope validation: confirmed.** With `ValidateScopes` on, Critical #1 would throw at the first request instead of quietly writing the wrong user. **Fix:** `builder.Host.UseDefaultServiceProvider(o => { o.ValidateScopes = true; o.ValidateOnBuild = true; })` (`dotnet-core` §1, l.18-41). Turn it on together with fix #1, or every request will fail.

### Outside my area (brief)
- **National ID logged:** `LabClient.cs:11` puts the national ID in the URL path, and `HttpClient` logs request URIs at Information, the default level (`appsettings.json:16`). Raise `System.Net.Http.HttpClient` to Warning, or redact the URI.
- **No timeouts or resilience** on either typed client.
- **Health data in the SMS:** the SMS text names the test (`ResultEndpoints.cs:43`). Check that this is acceptable.

### Migration safety
There are no migrations in the repo; the tests create the schema from the model. Before production, generate a reviewed up/down script pair. Script the new composite index on its own, with `IsCreatedConcurrently()` and without `--idempotent`, and start the script with `SET lock_timeout`. `Program.cs` never calls `Migrate()` or `EnsureCreated()`, which is correct.
