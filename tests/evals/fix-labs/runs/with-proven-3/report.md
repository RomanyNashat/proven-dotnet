I've applied the review: 17 of the 21 findings are fixed in full, two in part, and two are left for the owners. The service builds with no warnings in Debug and Release. All 99 new tests pass, and neither project has a known-vulnerable package (I ran the scan both projects with `dotnet list package --vulnerable --include-transitive`).

**How it was tested.** Tests are in `LabResults.Tests/`. They run the app in-process with `WebApplicationFactory` (no database), using tokens signed in the test and stubbed lab and SMS services. Before any fix, I ran the API tests against the original code and 17 of 20 failed, mostly the 403 from finding 1. After the fixes I put the old HTTP logging back on `LabClient` as a check, and the log test caught the national ID in 7 log lines. Coverage is 88% of lines and 84% of branches; the gaps are the paths that need PostgreSQL.

**Fixed (file — what — why)**
1. `Api/KeycloakJwt.cs`, `Program.cs` — roles are now copied out of Keycloak's `realm_access` and `resource_access["lab-results"]` claims. `MapInboundClaims=false`, `ClockSkew` is 30 s, and `RequireHttpsMetadata=true` (already the default, so nothing changes for the hidden tests). The clinician policy also requires a `sub`. Before, every clinician got a 403.
2. `Infrastructure/AuditInterceptor.cs`, `LabDbRegistration.cs`, `LabDbContext.cs`, `CurrentUser.cs` — the interceptor no longer holds state: it reads `CallerId` from the context, which is set from the caller's `sub` each time a request borrows a pooled context. It refuses the save when there is no caller. Scope validation is on in every environment. Before, every row was stamped with the first clinician who called after start-up.
3. `Application/NotificationWorker.cs`, `NotificationQueue.cs` — the worker catches every exception (logging only its type) and empties the queue on shutdown. Before, one SMS timeout stopped the whole host. The request now queues the SMS without waiting, so a full queue can't hold up the POST after the save and cause a client retry to save a duplicate.
4. `Infrastructure/HttpClientsRegistration.cs`, `StatusOnlyLoggingHandler.cs` — the default HTTP logging is removed from both clients, and my own line logs only the status code and exception type. Before, the national ID in the lab URL was logged.
5. & 10. `Api/*Validator.cs`, `ValidationFilter.cs`, `Application/NationalId.cs`, `Digits.cs` — every request is validated before the handler runs. National IDs must be `^[12][0-9]{9}$`, with Arabic-Indic digits converted first. `Value` must fit `numeric(10,3)` and `PatientId` must be above 0. This closes the `..` path trick, the 500 on a null ID and the database overflow error.
6. `Application/SaudiMobile.cs`, `Notification.cs`, `Resources/SmsTexts.resx`, `Api/PerCallerRateLimits.cs` — the phone must be a Saudi mobile, converted to `+9665…`. The SMS is now a generic text from a resource and no longer names the test. Recording and lookups are rate-limited per caller at 60 a minute, configurable.
7. `Api/ResultCursor.cs`, `ResultEndpoints.cs`, `LabResultConfiguration.cs` — paging is ordered by time then id, `next` is an opaque cursor holding both, and a bad cursor returns 400. The index is now `(ReceivedAt, Id)` descending.
8. `LabResultConfiguration.cs` — `Notes` is limited to 1000 characters, and the validator matches.
9. `ResultEndpoints.cs` — the log line has `PatientId` instead of the national ID. `Masking.cs` was deleted because nothing used it any more.
11. `Api/UnexpectedExceptionHandler.cs`, `SecurityHeaders.cs`, `Program.cs` — added ProblemDetails, a global exception handler that reveals nothing internal, security headers on every response including errors, HSTS for one year, and forwarded headers. A 404 from the lab now gives an empty list (`LabClient.cs`).
13. `HttpClientsRegistration.cs`, `BaseAddressOptions.cs`, `LabDbOptions.cs` — both clients have the standard resilience handler; the SMS POST is never retried. Settings are validated at start-up.
15. `appsettings.json`, `LabDbRegistration.cs` — `SSL Mode=VerifyFull`, `Maximum Pool Size=20`, connection and command timeouts, and `EnableRetryOnFailure(3)`.
16. `LabResults.csproj` and the test csproj — the package audit is on for direct and transitive packages, any vulnerability fails the build, and nullable warnings are errors. I put this in the two project files, not `Directory.Build.props`, so it doesn't fail the hidden test project's own packages.
17. – 18. The id column is now identity ALWAYS, and the list query maps straight to the response instead of loading whole entities.
20. – 21. The `Location` header pointing at a route that doesn't exist is gone (still 201 with the result), and the log category is a name, not the request DTO.
- Not in the review: `Domain/LabResult.cs` rounds `ReceivedAt` to UTC microseconds. Without that, the POST response shows a different time from the one a later GET reads back.

**Found but not fixed**
- **12, SMS outbox:** not done. It would store phone numbers in the database, which needs encryption at rest and a one-at-a-time sender — a design decision for the owners. The review's minimum (finding 3) is done, but queued SMS are still lost if a pod restarts.
- **14, care-team scoping:** for the owners, as the review settled; filtering `GET /results` would change the contract. Reads and lookups are now written to the log, but that is not a stored audit trail.
- **19, layering:** partly done. The SMS sender is behind an `ISmsSender` interface in Application. The endpoints still use `LabDbContext` directly and return `LabOrder` from Infrastructure, to keep the shapes the hidden tests use.
- **Migration scripts:** none written. There's no database here to generate and check them against. The new index should go in its own script with `CREATE INDEX CONCURRENTLY` and a `lock_timeout`.
- **Forwarded headers:** only loopback proxies are trusted. The ingress network has to be added for each deployment.
- **Journal:** I couldn't write `.claude/journal.md` because the permission was refused.

**Not checked:** anything that needs PostgreSQL. That means the insert, the paging query and its `EXPLAIN`, the identity-always column, and that recorded results really get the caller's `sub` against a real database. Also not checked: real Keycloak tokens, and whether the 60-a-minute rate limit is too low for the hidden tests if they create many results with one token (it can be raised in config).
