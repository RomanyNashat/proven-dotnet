# LabResults review

The service builds with 0 warnings. `LabResults.Tests/` has 29 passing tests: unit tests, plus in-process `WebApplicationFactory` tests for auth and lookup that use signed tokens and a fake lab API. Nothing that needs PostgreSQL was run, so `POST /results`, `GET /results` and the audit stamping have only been checked by reading the code and by unit tests.

## Fixed

| # | File | Problem | Why it matters / fix |
|---|------|---------|----------------------|
| 1 | `Program.cs`, new `Infrastructure/KeycloakRolesTransformation.cs` | `RoleClaimType = "realm_access.roles"`. Keycloak puts roles inside a JSON object (`realm_access: { roles: [...] }`), so no claim has that name and `RequireRole("clinician")` failed for every user. | Every real clinician got 403. Added an `IClaimsTransformation` that turns `realm_access.roles` and `resource_access["lab-results"].roles` into claims of the identity's own role type. It doesn't repeat work if run twice, and a malformed claim grants nothing. Also set `MapInboundClaims = false` so `sub` keeps its name. |
| 2 | `Program.cs`, `Infrastructure/AuditInterceptor.cs`, `Infrastructure/CurrentUser.cs` | `AddDbContextPool` builds its options once, from the root provider. That resolved the *scoped* `AuditInterceptor` and `CurrentUser` a single time, and `CurrentUser` read the user in its constructor. Scope validation is off in Production, so nothing complained. | Every result got the `RecordedBy` of whoever (or `"system"`) was current when the pool was built: a broken audit trail on medical data. `CurrentUser` now reads `sub` from the request each time it is asked. Both are singletons, which is safe with pooling. The interceptor refuses to save a result without an authenticated user instead of writing `"system"`. It also handles the sync `SavingChanges` now. The `clinician` policy also requires a `sub`. |
| 3 | `Api/ResultEndpoints.cs`, `Infrastructure/LabDbContext.cs` | Pages were split on `ReceivedAt < before` only. | Results with the same timestamp were skipped across page boundaries. This always happens with a fixed `TimeProvider`, and also with batch imports. Now uses an opaque keyset cursor on `(ReceivedAt, Id)`, ordered by `ReceivedAt DESC, Id DESC`. It fetches `take+1` rows, so `next` is null on the last page and there is no empty extra page. Matching descending indexes were added. |
| 4 | `Api/ResultEndpoints.cs` | `DateTimeOffset.Parse(before)` on user input threw, giving a 500. A non-UTC offset would also make Npgsql throw on `timestamptz`. | A bad cursor now returns 400. The cursor is always UTC. |
| 5 | `Domain/LabResult.cs` | `ReceivedAt` kept .NET's 100 ns precision, but PostgreSQL stores microseconds. | The `POST` response didn't match what `GET` returned later, and cursors could be off. The time is now cut to microseconds when the result is recorded. |
| 6 | `Api/ResultEndpoints.cs`, `Infrastructure/LabDbContext.cs` | Validation was incomplete. `Value` wasn't checked against `numeric(10,3)` (overflow gave a 500; extra decimals were rounded without notice). `PatientId`, `NationalId` and `Phone` weren't checked (a null phone went to the SMS queue). `Notes` had no length limit. All errors were reported under `"Test"`. | Added `ResultValidation`, with one error per field: patient id > 0, national id of 10 digits, phone in E.164 format, test ≤ 40, unit ≤ 16, value fits `numeric(10,3)`, notes ≤ 2000 (also in the model). |
| 7 | `Api/ResultEndpoints.cs` (lookup), `Infrastructure/LabClient.cs` | `nationalId` went into the lab URL with no check. `Uri.EscapeDataString` doesn't escape `.`, so `".."` resolved `patients/../orders` to a different endpoint of the lab API. A null value caused a 500. | Path manipulation against a partner API. The national id must now be exactly 10 digits, otherwise 400. |
| 8 | `Api/ResultEndpoints.cs`, `Infrastructure/LabClient.cs`, `Program.cs` | Any lab failure (error status, timeout, bad JSON) gave an unhandled 500. The default `HttpClient` timeout is 100 s. | A lab 404 now returns an empty list. Other failures return 502 with problem details. Timeouts are 10 s for the lab and 15 s for SMS. |
| 9 | `Application/NotificationQueue.cs` | The worker caught only `HttpRequestException`. A timeout (`TaskCanceledException`) or any other error ended `ExecuteAsync`, and from .NET 8 on that **stops the whole host**. | One slow SMS gateway call took down the service. The worker now catches everything except shutdown and logs without the phone number. |
| 10 | `Application/NotificationQueue.cs`, `Api/ResultEndpoints.cs` | Enqueueing used `WriteAsync` with the request token *after* the result was saved. With the queue full, the request hung, and if the client gave up, the result was saved but the client saw an error and retried. | Duplicate results. Now uses a non-blocking `TryEnqueue`, and logs a warning if the queue is full. |
| 11 | `Api/ResultEndpoints.cs` | The SMS text included the test name ("نتيجة تحليل HbA1c جاهزة"). | That sends health information to a phone and through a third-party gateway. The text is now generic ("your test result is ready"). |
| 12 | `Application/Masking.cs` | The regex masked only runs of exactly 10 digits. Ids of another length or with letters were logged in full, and an 11-digit id leaked 5 digits. A null id threw. | PII in logs. Now every character except the last 4 is masked, whatever the format. |
| 13 | `appsettings.json` | `HttpClient` logs at Information level include the request URL, which contains the national id (`patients/{nationalId}/orders`). | PII in logs. Set `System.Net.Http.HttpClient` to `Warning`. |
| 14 | `Program.cs` | No exception handler or problem details in Production. | Errors now return problem details (`AddProblemDetails`, `UseExceptionHandler`, `UseStatusCodePages`). |

## Found but not fixed

- **SMS notifications are kept only in memory.** Anything queued but not yet sent is lost on restart or deploy, and failed sends aren't retried. The right fix is a transactional outbox table written in the same `SaveChanges` as the result, plus a worker with retries and an idempotency key. That is a design change (it would also mean storing phone numbers), so I left it.
- **No per-patient access control.** Any clinician can list every patient's results and look up any national id. The spec defines the routes that way. I added an optional `patientId` filter to `GET /results`; it changes nothing for existing callers. Real restrictions (care-team checks) and access auditing for reads and lookups need product decisions.
- **No retry or circuit breaker** for the lab API (only timeouts). `Microsoft.Extensions.Http.Resilience` could be added for the GET. SMS should not be retried automatically without an idempotency key, or patients may get duplicate messages.
- **No schema migrations.** The tests create the schema from the model. Production needs EF migrations; the model now has new indexes and a length limit on `Notes`.
- **National id is assumed to be 10 digits** (from the masking example and the +966 phone numbers). If other id formats are valid, change `ResultValidation.IsNationalId`.
- **No readiness check** (database or dependencies), no rate limiting, and no `AllowedHosts` or forwarded-headers setup. These depend on how the service is deployed.
- `RecordedBy` is limited to 64 characters. Keycloak `sub` values are UUIDs (36 characters), so this is fine unless the identity provider changes.
