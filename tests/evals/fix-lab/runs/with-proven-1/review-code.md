## Code Review: HomeReadings (pre-production, code-reviewer)

### Summary
Not ready for production. Four kinds of fault: patients can read each other's data (IDOR and a shared cache key). Nurses can get duplicate alerts, and high readings can be lost. The meter's value is parsed under the Arabic culture, so readings fail or come out wrong. A path traversal lets an upload write anywhere on disk. All 16 files were read.

**Known-traps item `Program.cs:7` (scope validation off in Production): CONFIRMED, severity info.** `CreateBuilder` turns on ValidateScopes and ValidateOnBuild in Development only. The developer runs the tests in Production, so these checks never run anywhere. I traced the current graph and found no captive dependency today: the singletons PhotoStore, ReadingNotifier and TimeProvider take only singletons or `IServiceScopeFactory`. So it guards future changes and fixes no current bug. Fix: `ValidateServicesInEveryEnvironment()` (dotnet-core, Rules: "on in every environment").

### Critical (must fix)
1. **IDOR**, `Application/ReadingQueries.cs:12-16`: `GetAsync` filters by `Id` only. Any patient can step through the int ids and read every glucose value and note. **Fix:** add `&& r.PatientId == patient.Id` to the query, so a missing or foreign record is a 404. (api-design §11, rules/security.md "Every lookup by ID checks ownership")
2. **Another patient's data from the cache**, `ReadingQueries.cs:32`: the key `"readings:latest"` is global. For the next minute, every patient gets the first caller's latest reading. It also caches `null`, and it is never cleared after `AddAsync`. **Fix:** key it per patient as `readings:v1:latest:{patientId}`, and remove the entry in `AddAsync`. (caching, key rules l.115)
3. **Duplicate nurse alerts (POST retried)**, `Program.cs:20-21`: `AddStandardResilienceHandler()` retries every method, POST included. A timed-out alert that actually arrived gets sent again, and the care-team system has no idempotency key. **Fix:** `.AddStandardResilienceHandler(o => o.Retry.DisableForUnsafeHttpMethods())`. Package 10.0.0 is at least 9.8.0, so this works. (polly-resilience l.44-64)
4. **Duplicate alerts (every pod sends)**, `Application/ReadingNotifier.cs:15`: each replica reads the same 50 unsent rows and sends them. **Fix:** claim rows with `FOR UPDATE SKIP LOCKED` and a `claimed_by` column, or run one sender at a time behind an advisory lock. (worker-patterns l.88-119, outbox l.494)
5. **Send, then mark sent**, `ReadingNotifier.cs:19-21`: if the process crashes or `SaveChanges` fails between the POST and the save, the alert is sent again. Without an idempotency key you have to choose deliberately. One option is to mark the row "Sending" (committed) before the POST, and on an unclear failure move it to "Unknown" for a person to check instead of resending blindly. **Fix:** decide this with the care team and record the decision. (outbox l.20-22)
6. **One care-team outage stops the service**, `ReadingNotifier.cs:33-36`: there is no try/catch. A failed send leaves `ExecuteAsync`, and with the default `StopHost` the whole API goes down, reading intake included, and the pod loops on restart. A row whose reading is missing makes `SingleAsync` (l.18) throw every run. **Fix:** `catch (Exception ex) when (ex is not OperationCanceledException)` with a log and back-off, per alert, so one bad row doesn't block the rest. (worker-patterns l.53-65)
7. **Lost alert for a high reading**, `Application/ReadingService.cs:16-23`: the reading and its alert are saved by two separate `SaveChanges` calls. If the second one fails, the reading is stored and no nurse is ever told. **Fix:** save both in one `SaveChanges`. Give the alert a `Reading` navigation, or use one transaction. (outbox, dual-write)
8. **The meter value is parsed under ar-SA, and "HI" crashes**, `ReadingService.cs:14` with `Api/LanguageMiddleware.cs:14`: the middleware makes `ar-SA` the *formatting* culture. `decimal.Parse("12.5")` then uses Arabic separators (`٫`), so it either fails or misreads. Glucose meters also show `HI` or `LO` out of range: `HI` throws, gives a 500, and the most dangerous readings get no alert. **Fix:** set only `CurrentUICulture` from the header. Parse with `CultureInfo.InvariantCulture` and `NumberStyles.AllowDecimalPoint`, map `HI` and `LO` explicitly (HI raises an alert), and return a 400 ValidationProblem for anything else. (localization §1 and table l.23-24, rules/csharp-standards.md "NEVER let ar-SA become the formatting culture")
9. **Readings filed under anyone's national ID**, `ReadingService.cs:7,14`: `NationalId` comes from the request body. A patient can file a reading under another person's ID, and the care team is alerted about the wrong patient. **Fix:** take it from the authenticated patient (a token claim or the patient record), never from the body. (rules/security.md)
10. **Path traversal on upload**, `Infrastructure/PhotoStore.cs:12`: `Path.Combine(folder, file.FileName)` with `../../x`, or with a rooted name (which discards the root), writes anywhere the process can write. There is also no size limit and no content-type allowlist. **Fix:** build the name on the server (`{readingId}/{Guid.CreateVersion7()}.jpg`), check the type against an allowlist, and set body limits in Kestrel, nginx and the ingress together. (rules/security.md "Validate file uploads", nginx l.43,58)
11. **Error details reach the client**, `Api/ErrorMiddleware.cs:16`: `ex.Message` and `InnerException.Message` are written to the response, and those carry Npgsql and EF error text. It also isn't ProblemDetails, and it fails if the response has already started. **Fix:** `AddProblemDetails()` with `UseExceptionHandler`, and a generic detail. (api-design §11 l.106,276)
12. **Patient data in the logs**, `ReadingService.cs:25`: `{@Reading}` sends NationalId, Value and Notes to the log sink. **Fix:** log `reading.Id` only, or a `[LoggerMessage]` with a classified parameter, plus the masking policy. (pii-masking l.15-25,60)
13. **Unbounded column (blocking DBA rule)**, `Infrastructure/ReadingsDbContext.cs:13-24`: `Notes` has no `HasMaxLength`, so it becomes `text`. **Fix:** `e.Property(r => r.Notes).HasMaxLength(500)`, or another bound you choose. (rules/efcore-rules.md)

### Warnings (should fix)
1. `NewReading.CollectedAt` (`ReadingService.cs:7`): if the app sends local Riyadh time without `Z`, the `DateTime` is Unspecified or Local, Npgsql refuses it, and the request fails with a 500. **Fix:** take a `DateTimeOffset`, convert it to UTC, and reject future times. (postgresql-patterns §2 l.55)
2. `ReadingQueries.cs:21`: "today" is the UTC day. For patients in Riyadh, readings from 00:00 to 03:00 local time land on the wrong day's chart. **Fix:** use the Riyadh day with the `FindSystemTimeZoneById` fallback. (localization §7 l.233-248)
3. There is no validation on `NewReading`. `Unit` is free text while `Reading.cs:34` assumes mmol/L, so every mg/dL reading (100 ≥ 11.1) raises an alert. A NationalId over 10 characters gives a 500. **Fix:** add a validator, and convert or restrict the unit. (rules/security.md Input Validation)
4. `Program.cs:31,40`: `/health/live` runs the DB check, so a database outage makes Kubernetes restart every pod. **Fix:** live checks nothing outside the process, and ready checks the DB. (kubernetes-dotnet l.124-139)
5. `PhotoStore.cs` and `appsettings.json:12`: photos go to a pod-local path, and the full absolute path is stored. With several replicas a photo exists on one pod only. **Fix:** object storage, with the row keeping a bounded key. (rules/efcore-rules.md "Outside the database")
6. `Program.cs:20` and `PhotoStore.cs:6`: config is read with `!` and no `ValidateOnStart`, so missing config surfaces at the first send or upload instead of at deploy. **Fix:** options with validation and `ValidateOnStart()`. (dotnet-core Rules l.327)
7. `Api/CurrentPatient.cs:12`: `int.Parse` on `sub`/NameIdentifier. The Authority looks like Keycloak (`/realms/`), whose `sub` is a UUID; if so, every request returns a 500. Confirm which claim carries the int patient id.
8. `ReadingNotifier.cs:18`: an N+1 query, one reading lookup per alert. **Fix:** join or project in the batch query.
9. Layering: Application depends on Api (`ICurrentPatient`) and Infrastructure (`ReadingsDbContext`, `CareTeamClient`, `PhotoStore`). (rules/architecture.md)
10. `POST /readings` has no idempotency key from the app, so a mobile retry creates a duplicate reading and a duplicate nurse alert.

### Suggestions
- `ReadingsDbContext.cs:31`: use a partial index on `sent_at IS NULL`, and add an FK and index on `ReadingId`.
- `LanguageMiddleware.cs:13`: the exact match on `"ar"` misses `AR` and `ar-SA`. Use `LanguageHeader.Parse`. (localization l.45-47)
- `CareTeamClient.cs:10`: dispose the response (`using var`).
- Move the magic strings `"home-readings"` and `"readings:latest"` to constants or config. Public types have no XML docs.

### Positive
- `TimeProvider` is used everywhere, including in `PeriodicTimer`.
- Classes are sealed; queries use `AsNoTracking` projections; keys are int identity-always; timestamps are `timestamptz`.
- There is no `Migrate()` call; HttpClient is a typed client from the factory; the worker opens a scope per run.
- The cancellation token is passed through; `AttachPhotoAsync` checks ownership; the alert threshold lives on the entity.

**Not checked:** there are no tests and no migration or DDL scripts in the folder, so neither was reviewed. Roslyn MCP was not available in this toolset, so symbol questions were answered by reading all 16 files directly.
