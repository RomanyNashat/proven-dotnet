## Security review: HomeReadings (/tmp/claude-0/labruns/with-proven-3/HomeReadings)

I read all 16 files. None of them contain text aimed at an AI reviewer. Skills cited are under /home/claude/proven-dotnet/.claude/skills/.

### Critical
1. **A01 IDOR: one patient can read another's reading.** `Application/ReadingQueries.cs:12-16`. `GetAsync` filters by `Id` only, and `GET /readings/{id:int}` (`Api/ReadingEndpoints.cs:17`) returns it to any valid token. Ids are sequential ints, so counting through them returns every patient's glucose value, time and free-text notes. **Fix:** add `&& r.PatientId == patient.Id` to the `Where`. Someone else's reading must come back as a 404. (auth-patterns §4, rules/security.md "Every lookup by ID checks ownership")
2. **A01: the "latest reading" cache is shared by all patients.** `Application/ReadingQueries.cs:32`. The key `"readings:latest"` has no patient in it. The first patient to open the app in a given minute fills the cache, and everyone else gets that patient's reading for 60 seconds. The endpoint runs on every app start, so this happens constantly. **Fix:** key it per patient, e.g. `$"readings:v1:latest:{patient.Id}"`, and clear that key in `AddAsync`. (caching, key guidance at line 115)
3. **A01/A05: path traversal in the photo upload, which can write any file.** `Infrastructure/PhotoStore.cs:12`. `Path.Combine(folder, file.FileName)` uses the client's Content-Disposition filename as it arrives. With `../../...` the file lands anywhere the process can write. With an absolute name (`/app/HomeReadings.dll`), `Path.Combine` drops the root entirely, and `File.Create` overwrites without asking: the app's binaries or config, or another reading's photo folder. There is no size limit, no type allowlist and no count limit either (`ReadingEndpoints.cs:26`). **Fix:** never use `FileName`. Write to `Path.Combine(folder, $"{Guid.CreateVersion7()}{ext}")` with `ext` taken from an allowlist (`.jpg`/`.png`), checked by magic bytes. Assert `Path.GetFullPath(path).StartsWith(rootFull + Path.DirectorySeparatorChar)`. Add `.WithMetadata(new RequestSizeLimitAttribute(5_000_000))` and a form-length limit. (rules/security.md "Validate file uploads ... no path traversal"; no skill has a tested sample for uploads)
4. **A01/A08: the patient chooses whose national ID goes on the clinical alert.** `Application/ReadingService.cs:7,14`, sent at `ReadingNotifier.cs:19`. `NationalId` comes from the request body, not from the authenticated patient, and nothing validates it. A patient (or a buggy app) can file readings under someone else's ID, and the care team's nurse then gets a high-glucose alert for the wrong person. **Fix:** remove `NationalId` from `NewReading` and look it up server-side from `patient.Id` (patient registry, or a verified token claim). (rules/security.md; owasp-aspnetcore §8 "Request DTOs, never entities")
5. **A09: patient data in the logs.** `Application/ReadingService.cs:25`. `{@Reading}` destructures the whole entity (NationalId, Value, Notes, PhotoPath) into every log event, and those go to the central log store. No masking is configured (`appsettings.json:14-17`, `Program.cs:9`). **Fix:** log `ReadingId`, `NeedsAlert` and the elapsed time only. Add the destructuring policy and pattern operators from pii-masking (Setup section), plus a test asserting a real-looking national ID never reaches the output. (pii-masking "Two layers", rules/security.md Data Protection)

### Warning
1. **A02/A10: error responses leak exception details.** `Api/ErrorMiddleware.cs:16` returns `ex.Message` and `InnerException.Message`: Npgsql errors such as `22001 value too long for type character varying(10)`, constraint and table names. In .NET 8+, a `FormatException` echoes its input, so the meter's text comes back too. The body isn't ProblemDetails and has no traceId. It also throws if the response has already started. **Fix:** `AddProblemDetails()` + `AddExceptionHandler<UnexpectedExceptionHandler>()` + `UseExceptionHandler()`, logging only the exception type and route. (api-design §2, owasp-aspnetcore §7)
2. **A09: the exception logged with the error carries patient values.** `Api/ErrorMiddleware.cs:14`. `LogError(ex, ...)` bypasses masking, and the `decimal.Parse` `FormatException` message contains the reading. **Fix:** as in the previous item: log the type and status, not the raw exception text. (pii-masking, "Neither layer touches the exception")
3. **A07: JWT setup.** `Program.cs:25-29`. `ClockSkew` is not set (defaults to 5 minutes; the rule is 30 s) and `MapInboundClaims` is left at its default. The Authority is a Keycloak realm, where `sub` is a UUID, yet `Api/HttpCurrentPatient.cs:12` runs `int.Parse` on it. With a stock realm every authenticated call is a 500, and through Warning 1 the 500 echoes the `sub`. **Fix:** use the auth-patterns §1 `AddKeycloakJwt` setup (`ClockSkew` 30 s, `MapInboundClaims=false`, audience from config). Map `sub` to the int patient id through a table, or use a dedicated claim with `TryParse` and return 401 when it fails. (auth-patterns §1, §5)
4. **A01: authentication is opt-in, not the default.** `Program.cs:30`. There is no fallback policy, so only the `/readings` group's `RequireAuthorization()` protects anything, and any new endpoint ships anonymous. **Fix:** `AddAuthorizationBuilder().SetFallbackPolicy(new AuthorizationPolicyBuilder().RequireAuthenticatedUser().Build())`. (auth-patterns §3)
5. **A05/A06: no input validation on `NewReading`.** `ReadingService.cs:7`. `Notes` has no length limit (and no `HasMaxLength`, so the column is unbounded `text`). `Unit` can be anything, but the alert threshold assumes mmol/L. Negative, out-of-precision and future `CollectedAt` values are all accepted. The `decimal.Parse` at `:14` uses the culture `LanguageMiddleware.cs:14` sets, which is `ar-SA` for Arabic users. A meter value that fails to parse is a 500, so a high reading is never saved and the care team never gets the alert. **Fix:** a FluentValidation validator (length matching the column, unit allowlist, value range, `CollectedAt <= now`), parse with `CultureInfo.InvariantCulture`, and keep `ar-SA` as the UI culture only. (api-design §3, localization §1, rules/security.md)
6. **A06: no rate limits.** Every high reading posted becomes a nurse alert, and photo uploads write to disk. One token, or an app stuck in a retry loop, can flood the care team. **Fix:** per-caller limiter on `POST /readings` and the photo upload. (api-design §6)
7. **A02: no security headers, HSTS or ForwardedHeaders.** Nothing in `Program.cs:35-41`. **Fix:** `UseApiSecurityHeaders` (headers set in `OnStarting`, `Cache-Control: no-store`), HSTS with a 365-day max-age, and ForwardedHeaders so HSTS is actually sent behind the ingress. (owasp-aspnetcore §1-2)
8. **Secrets: a password is committed.** `appsettings.json:3` contains `Password=change-me`. If production config doesn't override it, the service quietly connects with a default credential. **Fix:** no password in appsettings; use user-secrets locally and the vault or a K8s Secret in production. Fail at startup if it's missing. (secret-management, line 230)
9. **A04: national ID stored in plain text.** `ReadingsDbContext.cs:17`, copied onto every reading row. **Fix:** once Critical 4 is fixed, don't store it per reading at all. Otherwise encrypt it with AES-GCM, passing table/column/row as associated data. (encryption-patterns, rules/security.md "PII must be encrypted at rest")
10. **A03: dependency check not run, and the gate isn't wired.** I have no shell here, so `dotnet list package --vulnerable --include-transitive` hasn't been run. The service folder has no `Directory.Build.props` with `NuGetAudit`/`NuGetAuditMode=all` and NU1901-1904 as errors. Every package is pinned at 10.0.0 GA. **Fix:** add the props and run the command before release. Any hit blocks the release. (zero-vulns)

### Suggestion
- `Program.cs:9`: `builder.Services.AddSerilog(...)` makes Serilog the logger factory. If classified-logging redaction is added later, the redactor never runs. Use `builder.Logging.AddSerilog(...)` instead. (pii-masking, classified logging)
- Meter photos are health data sitting unencrypted on a plain volume, and `PhotoPath` stores the full server path. Store a storage key instead, in object storage with encryption at rest.
- `.DisableAntiforgery()` (`ReadingEndpoints.cs:28`) is fine as it stands: the API is bearer-only with no cookie auth.

### Known-traps item (`Program.cs:7`, ValidateScopes/ValidateOnBuild)
**Confirmed, info, mostly code-reviewer's area.** Production does skip both checks. No captive dependency exists today: `ReadingNotifier` uses `IServiceScopeFactory`, and `PhotoStore` takes only `IConfiguration`. The security angle is that these checks are the safety net if a scoped `ICurrentPatient` is ever captured by a singleton, which would be another cross-patient leak. The tests run in Production, so they wouldn't catch it either. Turn both on. (dotnet-core)

### Outside my area (for the other reviewers)
- `TodayAsync` uses the UTC day, so readings taken 00:00-03:00 Riyadh time count toward the previous day.
- `AddStandardResilienceHandler` retries the alert POST, but the care team system has no idempotency key, so retries can send duplicate nurse alerts.
- An exception in `RunOnceAsync` ends `ExecuteAsync`, and with the default StopHost behaviour that stops the whole host.
- The reading and its alert are saved in two separate `SaveChanges` calls, so a crash between them loses the alert.
