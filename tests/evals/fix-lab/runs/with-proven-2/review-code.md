## Code Review: HomeReadings (pre-production, code-reviewer)

### Summary
The code is small and mostly idiomatic (sealed types, TimeProvider, typed client, scoped work inside the worker, int identity keys, timestamptz). It is not ready for production: it has a cross-patient data leak (IDOR plus a shared cache key), a path-traversal write, a worker that can stop the whole API and send duplicate nurse alerts, and culture-dependent parsing of the meter value.

### Known-traps verdict
**Confirmed, as a Suggestion.** `Program.cs:7` uses the default provider options, so ValidateScopes and ValidateOnBuild are off in Production. There is no captive dependency today: the singletons `PhotoStore` and `ReadingNotifier` take only singletons and `IServiceScopeFactory`, and `CareTeamClient` is resolved inside a scope. It still matters because your tests run in Production, so a future singleton-takes-scoped mistake would never fail a test run. Fix: `builder.Host.UseDefaultServiceProvider(o => { o.ValidateScopes = true; o.ValidateOnBuild = true; })`. Source: dotnet-core, "The host" and Rules.

### Critical (must fix)
1. **IDOR** at `Application/ReadingQueries.cs:12-16`. `GetAsync` filters by `Id` only. Ids are sequential ints, so any signed-in patient can read anyone's glucose value and notes by counting up `/readings/{id}`. Fix: add `&& r.PatientId == patient.Id`, so someone else's reading returns 404. Source: api-design §11, rules/security.md.
2. **One patient's reading shown to another** at `Application/ReadingQueries.cs:32`. The cache key `"readings:latest"` is shared by all patients. The first patient's latest reading is served to every patient for a minute. Fix: key `$"readings:v1:latest:{patient.Id}"` (invariant culture), and remove the entry in `AddAsync` so a patient's new reading shows up at once. Source: caching (keys).
3. **Path traversal** at `Infrastructure/PhotoStore.cs:12`. `Path.Combine(folder, file.FileName)` takes a filename the client controls. With `../..` or an absolute path (Combine then returns the absolute path), a patient can overwrite any file the process can write. There is also no size limit or content-type allowlist. Fix: name the file on the server (`{Guid.CreateVersion7()}.jpg`), allow only image types, cap the size, and store a bounded key rather than a full server path. Better still, use object storage, because a local volume isn't shared across pods. Source: rules/security.md (file uploads), efcore-rules.md (objects outside the DB, row keeps the key).
4. **One failure stops the whole service** at `Application/ReadingNotifier.cs:33-36`. Nothing catches exceptions in the loop. A care-team 4xx/5xx after the resilience handler's 30 s budget, or a missing reading (`SingleAsync`, line 18), escapes `ExecuteAsync`. `BackgroundServiceExceptionBehavior.StopHost` then takes the patient API down with it. A poison alert, always first by `OrderBy(Id)`, does this again a minute after every restart, so you get a crash loop and no alert after it is ever sent. Fix: `try/catch (Exception ex) when (ex is not OperationCanceledException)` around each run, and also around each alert. Give alerts an attempt count and a failed state so one bad row can't block the rest. Source: worker-patterns ("Periodic work", "A polling worker").
5. **Duplicate nurse alerts** at `Program.cs:20-21`, `ReadingNotifier.cs:19-21` and `ReadingNotifier.cs:15`. The care team's system has no idempotency key, but:
   - (a) `AddStandardResilienceHandler()` retries POSTs. A slow but successful POST is cut at the 10 s attempt timeout and sent again.
   - (b) Passing `stoppingToken` into `SendAlertAsync` cancels an in-flight POST on SIGTERM. The POST may still have been delivered, but the alert stays unmarked and is resent on the next start.
   - (c) With more than one replica, every pod reads the same 50 unsent rows.

   Fix: `o.Retry.DisableForUnsafeHttpMethods()` (package 10.0.0 is at least 9.8, fine). Don't cancel a send that has started; mark it straight after. Claim rows with `FOR UPDATE SKIP LOCKED`, or run a single relay under an advisory lock. Accept and document the remaining at-least-once window after a crash, and ask the care team for an idempotency key. Source: polly-resilience ("Never retry a POST by default"), worker-patterns (claiming), outbox (one relay, at-least-once).
6. **Meter value parsed with the request's culture** at `Application/ReadingService.cs:14` and `Api/LanguageMiddleware.cs:14`. `decimal.Parse(request.Value)` runs under `CurrentCulture = ar-SA` for Arabic users. Under some ICU builds the decimal separator is `٫`, so `"11.5"` fails, and the result depends on which machine runs it. Meters also show `HI` or `LO` text. A failed parse is a 500, so the most dangerous readings are the ones lost. On an image without ICU, `new CultureInfo("ar-SA")` (line 8) throws and every request fails. Fix: set only the UI culture from `x-language` (never `CurrentCulture`), and use `decimal.TryParse(value, NumberStyles.AllowDecimalPoint, CultureInfo.InvariantCulture, …)` that returns 400 on failure. Decide with the product team how HI/LO is recorded and alerted. Source: localization §1, §2, §13; rules/csharp-standards.md.
7. **Patient identity taken from the request body** at `Application/ReadingService.cs:7,14`. `NationalId` comes from the body, not from the authenticated patient. A patient can file readings, and trigger nurse alerts (`ReadingNotifier.cs:19`), under someone else's national ID. Fix: resolve the national ID from the patient's record or claim, and drop it from `NewReading`. Source: rules/security.md (ownership).
8. **Alert rule ignores the unit** at `Domain/Reading.cs:34`. `Value >= 11.1` assumes mmol/L, but `Unit` is free text and isn't validated. A mg/dL meter (common in KSA) reporting a normal 120 alerts a nurse every time. Fix: make the unit a closed set (an enum stored as a bounded string) and convert to mmol/L in the domain, or reject other units. Source: ddd-patterns (behaviour and invariants in the entity).
9. **PHI written to logs** at `Application/ReadingService.cs:25`. `{@Reading}` destructures NationalId, Value and Notes into every log event. No masking policy is configured (`Program.cs:9`). Fix: log `ReadingId` and `PatientId` only, and add the destructuring policy plus pattern masking. Source: pii-masking, rules/security.md.
10. **Exception text sent to the client** at `Api/ErrorMiddleware.cs:16`. `ex.Message` and the inner message are written to the response, including Npgsql and FormatException details. Client aborts also log as 500s, and if the response has already started, writing to it throws. Fix: `AddProblemDetails` with an `IExceptionHandler` and `UseExceptionHandler`, returning a generic title plus `traceId`. Source: api-design §2, §11.
11. **Unbounded column (blocking DBA rule)** at `Infrastructure/ReadingsDbContext.cs:13-24`. `Notes` has no `HasMaxLength`, so it becomes a `text` column. Fix: `HasMaxLength(500)` (or similar), with the same limit in a validator. Source: rules/efcore-rules.md.
12. **High reading saved without its alert** at `Application/ReadingService.cs:17-23`. The reading and the alert use two `SaveChangesAsync` calls. If the second fails, the high reading is stored and the alert is lost. The client then sees a 500 and retries, which duplicates the reading. Fix: give the alert a navigation to the reading (or create it from the aggregate) and save once.

### Warnings (should fix)
1. `ReadingService.cs:7` has no validator. `NationalId` over 10 characters or `Unit` over 16 becomes a DB error and a 500. Add FluentValidation with limits that match the columns. Source: api-design §3.
2. `ReadingService.cs:7` / `Reading.cs:29`: `CollectedAt` is a `DateTime`. If the app sends local time without `Z` or with `+03:00`, the Kind is Unspecified or Local and Npgsql refuses the write, so every POST fails. Use a `DateTimeOffset` and convert it to UTC. Source: postgresql-patterns §2.
3. `ReadingQueries.cs:21`: "today" is the UTC day. Riyadh patients see yesterday's readings between 00:00 and 03:00, and early readings land on the wrong day. Use `RiyadhTime.Zone` with the fixed-offset fallback. Source: localization §7.
4. `Program.cs:40`: the liveness check includes the DB check, so a database outage restarts every pod. Use `Predicate = _ => false` for liveness and tag "ready" for readiness. Source: api-design §8.
5. `Api/CurrentPatient.cs:12`: `int.Parse` on the subject claim, with two `!`. The authority looks like Keycloak (`/realms/patients`), whose `sub` is a UUID, which would make every authenticated call a 500. Confirm the claim, use `TryParse`, and return 401.
6. `ReadingNotifier.cs:18` is an N+1: one query per alert, 50 per tick. Join or project the reading with the alert.
7. Layering: Application references Api (`ICurrentPatient`), Infrastructure (`ReadingsDbContext`, `PhotoStore`, `CareTeamClient`) and `IFormFile`. Move `ICurrentPatient` to Application and put storage and the client behind interfaces. Source: rules/architecture.md.
8. POST `/readings` has no idempotency key, so a mobile retry duplicates the reading and its alert. Have the app send a client-generated key (a GUID is allowed for externally created IDs).

### Suggestions
1. Validate configuration on start: `CareTeam:BaseAddress` and `Storage:PhotoRoot` are read with `!` (`Program.cs:20`, `PhotoStore.cs:6`). Bind them to options with `ValidateOnStart`. Source: dotnet-core Rules.
2. `Messages.cs`: the strings are hard-coded and match neither pattern. Pick JSON (no ICU needed) or resx. Source: localization §3.
3. `ReadingNotifier.cs`: use `CreateAsyncScope`, run once at start (do/while), and log the number actually sent. `CareTeamAlert.ReadingId` has no FK or index; a partial index `WHERE sent_at IS NULL` would suit the poll better.
4. `appsettings.json:3` commits a connection string with a password placeholder. Source it from secrets.
5. No migration scripts are present, so the schema the DBA will apply can't be reviewed here.

### Positive
Sealed types throughout; `TimeProvider` with `PeriodicTimer`; `IServiceScopeFactory` in the worker; a typed `HttpClient`; `AsNoTracking` and projections; `CancellationToken` passed through; ownership checked in `AttachPhotoAsync` and `TodayAsync`; int identity-always keys, timestamptz, `HasPrecision`; no `Migrate`/`EnsureCreated`; endpoints use TypedResults.

Not checked: tests (none in the folder), nginx/forwarded headers (deployment not stated), JWT settings beyond the above (security reviewer's area). The Roslyn MCP wasn't available, so I read all 16 files directly.
