# ClinicQueue: .NET 8 → .NET 10

The service builds on net10.0 with warnings as errors (0 warnings). `dotnet list package --vulnerable --include-transitive` reports nothing. The 10 unit and in-process tests in `ClinicQueue.Tests/` pass. Nothing that needs PostgreSQL was run, so the database paths are covered only by model and SQL-translation checks.

## Changes

| File | What | Why |
|---|---|---|
| `ClinicQueue/ClinicQueue.csproj` | `net8.0` → `net10.0`. JwtBearer 8.0.11 → 10.0.15. Npgsql.EntityFrameworkCore.PostgreSQL 8.0.10 → 10.0.3. | Move off the unsupported runtime. Package majors match the framework. |
| `ClinicQueue/ClinicQueue.csproj` | Removed `System.Linq.Async`. | .NET 10 ships `System.Linq.AsyncEnumerable` in the BCL, and the package's extension methods clash with it. Nothing needs it any more (see QueueSnapshots). |
| `ClinicQueue/ClinicQueue.csproj` | Removed `EnableUnsafeBinaryFormatterSerialization` and the `SYSLIB0011` suppression. | BinaryFormatter is gone (see below). |
| `ClinicQueue/ClinicQueue.csproj` | NU1901–NU1904 are now errors (they were in `WarningsNotAsErrors`). Added `NuGetAuditMode=all` and CS8600/8602/8603 as errors. | A known-vulnerable package, direct or transitive, now fails the build instead of passing silently. No current package trips it. |
| `ClinicQueue/Application/QueueSnapshots.cs`, new `QueueSnapshot.cs`, new `QueueSnapshotSerializer.cs` | Cache entries are now System.Text.Json instead of BinaryFormatter. `QueueSnapshot` is now an immutable record. The query projects `Position` in SQL (`Select` before `ToArrayAsync`) instead of streaming whole rows through System.Linq.Async. The cache key is built with `InvariantCulture`. | **This was a production break.** On .NET 9 and later, BinaryFormatter throws `PlatformNotSupportedException` even with the opt-in flag, so every `GET /clinics/{id}/queue` would have returned 500. BinaryFormatter is also an RCE risk. The cache is in-memory, so no old entries carry over a deploy. |
| `ClinicQueue/Application/DirectoryWarmer.cs` | The first `Refresh()` moved from `ExecuteAsync` into an overridden `StartAsync`, before `base.StartAsync`. | **Behaviour break in .NET 10:** `BackgroundService` now runs all of `ExecuteAsync` in the background, including the synchronous part before the first `await`. Without this change the host would start serving before the clinic list loaded, and the first `GET /clinics` would return `[]`. A failed first load still stops start-up, as before. A test reproduces the bug (it failed before the fix). |
| `ClinicQueue/Application/ErrorHandler.cs` | Takes an `ILogger<ErrorHandler>` and logs the exception at Error, with method and path, through `[LoggerMessage]`. | **.NET 10 change:** the exception handler middleware no longer logs an exception that an `IExceptionHandler` marks as handled. Without this, production 500s would leave no log entry. The response is unchanged: a 500 ProblemDetails with no detail. |
| `ClinicQueue/Program.cs` | `KnownNetworks.Add(new Microsoft.AspNetCore.HttpOverrides.IPNetwork(...))` → `KnownIPNetworks.Add(System.Net.IPNetwork.Parse(Proxies:Network))`. Dropped the hand-rolled string split. | In .NET 10 the old API is obsolete (ASPDEPR005), which breaks the build when warnings are errors. Behaviour is unchanged: 10.42.0.0/16 is trusted, `ForwardLimit` is 2, and `/whoami` returns the `X-Forwarded-For` client. The in-process test covers a request from 10.42.0.7. |
| `ClinicQueue/Domain/Visit.cs`, `ClinicQueue/Api/QueueEndpoints.cs` | `Visit.Day` and the day parsing now use `DateOnly` instead of `DateTime` (`DateOnly.TryParseExact`, same format and culture). | The column is `date` (unchanged, still `HasColumnType("date")`). `DateOnly` is Npgsql's natural mapping for it, with no time or `Kind` to drift. Request and response strings are identical (`yyyy-MM-dd`). |
| `ClinicQueue/Application/VisitReads.cs` | `ExecuteScalarAsync` + `(DateTime)` cast → `ExecuteReaderAsync` + `GetFieldValueAsync<DateOnly>`. Returns `DateOnly?`. | The cast depended on Npgsql's default CLR type for `date`. I understand newer Npgsql returns `DateOnly` there, which would make the cast throw on every `GET /visits/{id}/day`. I could not confirm this against a live database here. The typed read is correct either way. The ownership filter (`patient_id = @patient`) is unchanged. |
| `ClinicQueue.Tests/` (new) | xUnit, FluentAssertions `[7.0.0,8.0.0)` and `Mvc.Testing` 10.0.15. Tests: the warmer loads before `StartAsync` returns. The error handler logs and returns 500 with no detail. The snapshot JSON round-trips. The EF model maps `Visit.Day` → `day`/`date`. The queue query translates to a `date` parameter. An in-process Production host (fake `IClinicSource`, self-signed JWT, requests from 10.42.0.7 with `X-Forwarded-For`) covers `/whoami`, `/clinics`, the 401 without a token, and anonymous `/health/live`. | Checks the upgrade without a database. |

Unchanged: `Program` stays public, and the routes, request/response shapes, tables and columns, `IClinicSource`/`ClinicEntry`, JWT setup (default scheme, `Auth:Authority`, audience `clinic-queue`, `MapInboundClaims=false` so `sub` stays `sub`) and `appsettings.json` are as they were.

## Found but not changed

- **`POST /visits` position race.** It computes `COUNT(*) + 1` and then inserts, so two concurrent bookings for the same clinic and day can get the same position. A real fix needs a unique constraint on `(clinic_id, day, position)` or a locking or serializable transaction. That is a schema change, and the schema is fixed for this task.
- **`IClinicSource.Load()` is synchronous**, so the warmer makes a blocking DB call at start-up and every 10 minutes. The interface is part of the test contract, so I kept it.
- **`VisitReads` is a singleton that creates `NpgsqlConnection`s from the connection string.** It works (pooling is by connection string), but an injected `NpgsqlDataSource` would be the modern form. Not needed for the upgrade.
- **`BookVisit` has no validator.** The handler checks the day format and that the clinic exists, which covers the current fields.
- **`GET /clinics/{id}/queue` has no per-caller check.** Any authenticated user can read any clinic's positions. The response is only position numbers, with no patient data, so this looks intentional for the waiting-room screens. Worth confirming.
- **Missing defaults:** no HSTS or security headers, no `ClockSkew` tightening, no explicit `RequireHttpsMetadata`. Changing these alters production behaviour, and TLS ends at the ingress, so I left them out of an upgrade-only change.
- **`DirectoryWarmer` refresh failures.** A DB error during a 10-minute refresh crashes the host (`BackgroundServiceExceptionBehavior.StopHost`). This is the same as on .NET 8, so I left it.
- **`ASPNETCORE_` and nginx settings.** There is no Dockerfile or manifest in the folder. Whatever builds the image must move its base image to `mcr.microsoft.com/dotnet/aspnet:10.0`.
- **No prompt-injection or AI-directed text** was found in the repo.
